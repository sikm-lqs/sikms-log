*用本地 MiniMax H3 和 ComfyUI 复刻一支复古动画短片的制作笔记。*

![雨街上，两人各拿一把伞并肩走远](/images/writing/no-ordinary-love/cover.webp)

*成片最后一镜。*

看完《非凡之爱》，我想看看，把片里的两个人换成我和女朋友，会是什么样子。

第一版我尽量照着原片来。保留故事顺序、原来的音乐和复古动画气质，换成我们两个人的形象。原片有一段涉及外套，跟已经定下来的服装和后续镜头有冲突，我就先跳过了。这次做完的是一支大约 85 秒的短片，画面在本地用 MiniMax H3 生成。

## 先做一对看得出是我们的角色

一开始，我手上已经有两张生成过的人物形象图。我用它们做干净的人物参考，把正面、侧面、背面和常用表情分开。同框时按现实里约 175 和 162 厘米的关系来做。这样即便保留原片那种修长的身形，两个人站在一起也还有熟悉的比例。

第一版复古风出来时，我觉得轮廓、色块和阴影已经有想要的 2D 赛璐璐动画感。不过脸画得太概括，我和她那些能被认出来的地方也一起淡了。第二版保留衣服和体态，把脸型、眼形、眼镜和鼻口细节往原始形象拉回来。我最后选了第二版，再用它补齐三视图和表情图。

![左侧为复古风初版，右侧为最终采用的第二版](/images/writing/no-ordinary-love/character-versions.webp)

*左边是复古风初版，右边保留了更多脸部特征。*

![两位主角最终版本的正面、侧面及背面参考](/images/writing/no-ordinary-love/character-turnarounds.webp)

## 拆镜头的时候，我在看什么

我先从原片抽帧。自动检测给出了 82 个可能的切点，我对着前后帧筛了一遍，最后整理成 32 个镜头。跳过外套段以后，实际制作 31 个。

切点只给镜头划出边界。写分镜的时候，我还得想清楚观众在这几秒里要看到什么。比如男主用伞帮人解围，几次救场都有相似的反差：别人手忙脚乱，他还在喝咖啡，脚步也没乱。我在动作表里给这两件事都留了位置。

第 17 镜是个表情近景。男主刚用鸽群摆出爱心，镜头切到女主。她先侧眼看，接着短暂翻个白眼，嘴抿着，还有点脸红，最后才转头偷笑。早期版本的表情变化不够，我就专门补了中间那一下。这个近景里只有女主，男主和鸽群留在画外。

![第17镜的三张生成参考，依次是侧看、翻眼抿嘴和转头微笑](/images/writing/no-ordinary-love/storyboard-017.webp)

*第 17 镜的三张分镜参考图。中间那一下翻眼，给后面的笑留了个转折。*

每镜定好构图和道具之后，我再写动作表和验收条件。谁先伸手？伞尖碰到哪里？谁从哪边出画，下一镜接什么姿势？然后用 ChatGPT Image 按分镜制作参考图。简单镜头先准备首尾状态，有换手、接触或表情转折的镜头加中间图。图序、剧本、视频提示词和时长放在同一个制作包里。全量第一版用了 99 张参考图。

我先试了第 21 镜。女主在伞下回望，再抬手把笑藏起来。这个动作小，可以先看表演和人物形象能不能跟上。试片看过之后，我才把同样的做法铺到全片。

![从角色设计和拆镜到生成、看片、返修和剪辑的流程](/images/writing/no-ordinary-love/workflow.svg)

## 路人怎么突然穿上了女主的裤子

第一次全量生成，最明显的问题在第 1 镜。参考图里的路人穿米色大衣、戴红围巾。男主盖好井盖以后，画面里却出现了白上衣、深蓝裤子的人。我先怀疑自动化脚本给这一镜配错了图或者提示词。

回查 31 条 ComfyUI 提交记录后，那一批的文字、图片槽位和上传顺序都对得上。翻回提示词，我发现共用模板里塞了男女主的设定。包括第 1 镜在内，一共有 12 个女主没出场的镜头，还是写着她的白上衣和深蓝阔腿裤。模型读到了保持路人身份的要求，也读到了一套具体的女主造型。

后来我按 H3 的 R2V 结构重写了全片。每镜单独定义入画主体，给每张图分配用途，再按播放顺序写动作。六个字段分别放主体定义、任务概述、保留范围、详细镜头、环境声音和配乐。种子、时长和上传说明留在任务清单里。

比如喷泉边的硬币，我写的是它以薄边落在石沿，边转边往前滚，快从外沿跌出时才碰到伞尖。伞尖轻轻向上、向内一拨，硬币短暂升起，再落进水里。早期试片里，它会停在池边等人来救。把接触前后的运动写出来，才有机会做出那一下顺手的感觉。

我用同一批图、同样的种子和生成参数，把重写版直接全量跑了一遍。看片时，大部分镜头比上一版顺了许多。剩下的问题也能指到具体动作上了。

## 本地 ComfyUI 怎么接这批物料

我用的是 MiniMax H3 的 R2V（Reference-to-Video）工作流。清单为每个镜头记录一个镜头号、一份英文提示词、一组有序图片、一个种子和一个请求时长。脚本展开对应的工作流 JSON，把图片依序接进参考图节点，第一张对应提示词里的 Picture 1，再向本地 ComfyUI 提交。任务执行完，脚本按镜头号收回视频，保存真实提交的工作流和任务 ID。

我在动作表里可以标“约 1.9 秒伞尖碰到硬币”，但这一版普通 R2V 的图片输入没有逐张锁帧的时间参数。动作出现在哪一帧，要看实际生成。请求时长和剪辑占位也分开记。例如喷泉镜头请求 3.367 秒，按这套 24 fps 的工作流预计生成 90 帧，也就是 3.75 秒，剪辑时再选完整的动作区间。

后来的批次每次单开输出目录，留存提交文本、参考图顺序、图片哈希、参数和输出记录。第 7 镜在返修包里是第二条任务，脚本仍按原镜头号找到它的种子。这样只补跑其中几镜，也能回查当时用了哪张图、哪份文字。

在七镜修复项目里，第一行用来核对镜头清单，第二行才提交生成。这里的 all 读取的是修复项目的七条记录。

```bash
python run_reviewed_attempt.py --shots all
python run_reviewed_attempt.py --shots all --attempt repair-01 --execute
```

## 七个镜头，三种改法

重写完再看全片，第 2 镜的硬币动作有了，男主却像在滑步。回头看几张参考图，他的前伸腿确实太相似。我改了两张中间图，一张给单腿承重、另一腿前摆，下一张给前摆腿落脚。伞尖和硬币的接触位置也得一起检查。

![喷泉镜头的滚币参考图，左侧是旧版，右侧增加了单腿支撑和前摆姿态](/images/writing/no-ordinary-love/walk-revision.webp)

*同一个动作节点，左图是旧参考，右图是返修参考。*

第 8 镜的问题要往前追到拆解。我最初写成男主从倒立舞者前面走过，舞者自己收腿继续转。回看密集抽帧时，能看到伞往纸板边缘下探，舞者随后收腿、落掌并稳住。我把这次帮忙补进剧本，重做了一张接触图，让伞尖压在纸板上。那一下有了，舞者停下来的原因才看得出来。

![第8镜修订后的接触参考，伞尖压住纸板近侧边缘](/images/writing/no-ordinary-love/cardboard-contact.webp)

另外五镜也是看片时逐一记下来的。

| 镜头 | 看片时看到的问题 | 返修时改了什么 |
| --- | --- | --- |
| 007 店门 | 男主朝着店门往后退，像在倒放 | 改中间图的朝向，补上转身、朝左迈步和出画 |
| 012 服务员 | 伞接住了人，随后还是坐到地上 | 写清楚伞向上托起整个身体，等双脚站稳才撤 |
| 015 花丛 | 两个人像站着演完了献花 | 从开头就向右走，侧向跟拍，递花和拒绝都在行进中发生 |
| 018 扶梯 | 女主经过男主面前时，人物轮廓扭了一下 | 明确近侧通道和遮挡，等她走过再换手、摸头、跟上 |
| 020 窗口泼水 | 水已经落下，伞才挡过去 | 把举伞和倾桶写成并行动作，让主水幕先撞上伞面 |

七镜一共换了四张参考图，七份提示词都做了调整。我单独重跑这七镜，按原镜头号换回时间线。把它们放回前后镜头之间，带上原来的音乐完整检查了一遍，才确认了现在发布的这一版。

![成片中男主经过喷泉，用伞尖拨动池沿的硬币](/images/writing/no-ordinary-love/final-fountain.webp)

*成片里的喷泉镜头。走路、喝咖啡和拨硬币发生在同一镜里。*

![成片中男主撑伞，女主抬手掩住笑](/images/writing/no-ordinary-love/final-shelter.webp)

*成片里的伞下回望，也是我最早拿来试做的镜头。*

花丛里那一大束花，她抬手就拒绝了。走到窗台边，他只递过去一枝，她倒接住了，又把它别回他发间。这两处放在一起，前面的拒绝和后面的回应就都看得见了。最初我只是想看看，换成我们两个人会是什么样。最后成片里，除了脸，也有了这些小动作。
